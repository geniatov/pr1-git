# Практическая работа № 1

**Тема:** основы работы с Git и GitHub.

## Цель

Научиться создавать репозиторий, сохранять изменения в коммитах, работать с ветками, объединять их и отправлять проект на GitHub.

## Ход работы

1. Создан пустой репозиторий `pr1-git` и скопирован на компьютер командой `git clone`.
2. Подготовлена структура проекта: `main.py`, `README.md`, `docs/info.txt`.
3. Начальные файлы добавлены в индекс командой `git add` и сохранены коммитом.
4. В ветке `feature/add_greeting` функция `main` изменена для вывода персонального приветствия. Ветка объединена с `main`.
5. В ветке `feature/config` создан файл `config.ini`. Для объединения использована команда `git merge --no-ff`.
6. История коммитов просмотрена командой `git log --oneline --graph --all`.

## Ответы на контрольные вопросы

**1. Чем отличаются `merge` и `rebase`?**  
`merge` объединяет изменения веток и сохраняет в истории коммит слияния. `rebase` переносит коммиты одной ветки поверх другой, переписывая их историю.

**2. Для чего используется `--no-ff`?**  
Параметр `--no-ff` создаёт отдельный коммит слияния, даже если Git мог бы просто передвинуть указатель ветки. Так в истории явно виден факт объединения веток.

**3. Что делать при ошибке `rejected (non-fast-forward)`?**  
Сначала получить изменения из удалённого репозитория, например командой `git pull origin main`. Если возник конфликт, разрешить его, добавить исправленные файлы и завершить слияние коммитом. Затем повторить `git push origin main`. Не следует без необходимости использовать `git push --force`: эта команда может перезаписать удалённую историю.

**4. Что такое индекс и зачем нужна команда `git add`?**  
Индекс — область, в которой выбираются изменения для следующего коммита. `git add` помещает файлы или их изменения в индекс, чтобы включить их в коммит.

**5. Как отменить изменения в файле?**  
`git restore имя_файла` отменяет изменения в рабочей копии, ещё не добавленные в индекс. `git restore --staged имя_файла` убирает файл из индекса, но сохраняет сами изменения.

**6. Чем отличаются `git status` и `git diff`?**  
`git status` показывает общее состояние рабочей копии и индекса. `git diff` показывает изменения, ещё не добавленные в индекс, а `git diff --staged` — подготовленные к коммиту изменения.
